SOP & HTTP

Why HTTP Is Stateless

Each HTTP request/response is independent with no memory of previous interactions. The server doesn't inherently know if two requests come from the same user. This is why we need cookies and session tokens.

Same Origin Policy

Prevents scripts from one site from accessing data from another site. An origin is defined by scheme + host + port. Without SOP, any website could read your banking data.

⚡

Cross-Site Scripting (XSS)

What Is XSS?

Injecting malicious JavaScript into a web page so it runs in the victim's browser. The script executes with the same privileges as legitimate scripts on that page.

Consequences of XSS

  • Session hijacking — steal session cookies
  • Unauthorized actions — perform actions as the victim
  • Data theft — read sensitive page content
  • Phishing — modify page content to trick users

Stored vs Reflected XSS

📦 Stored XSS

Malicious script is saved in the database (e.g., in a comment). Executes for every user who views the page. More dangerous — persistent.

🪃 Reflected XSS

Malicious script comes from a crafted URL or request. Only affects users who click the malicious link. Requires social engineering.

🛡️

XSS Defences

Root Cause

Lack of proper input validation and sanitization. The server fails to distinguish between data and code when rendering user input into HTML.

HTML Encoding

Converting dangerous characters to their HTML entity equivalents so browsers treat them as data rather than executable code.

Cross-Site Request Forgery (CSRF)

What Is CSRF?

Tricking a victim's browser into sending authenticated requests to a target site using the victim's existing session cookies. The attacker doesn't need to steal credentials — the browser sends them automatically.

Root Cause

Servers cannot distinguish trusted same-site requests from forged cross-site requests. Both carry the same cookies.

CSRF Defences

DefenceHow It Works
SameSite=StrictPrevents cookies from being sent with cross-site requests
CSRF TokenA secret random token embedded in forms. Attackers can't read it due to SOP, so forged requests fail validation.
Referer CheckVerify the request originates from the same site
🔑

Session Management

Goal of Session Management

Maintaining user state across multiple requests in a stateless HTTP protocol. Sessions link requests to a specific authenticated user.

Session Token Dangers

VulnerabilityDescription
Tokens in URLsLeak through browser history, shared links, and Referer headers
Session FixationAttacker forces victim to use a known session ID before login. After login, attacker uses the same ID to hijack the session.
Predictable TokensIf tokens are guessable, attackers can forge them
