Fundamentals

Why OS-Level Understanding Matters

Understanding how programs execute at the operating system level is critical for security. It explains how vulnerabilities arise. By understanding memory layout, CPU execution, and stack behaviour, you can see why exploits like buffer overflows are possible.

The Trade-Off of Using C

C provides fast, low-level control — but has a high risk of memory errors due to:

  • No automatic bounds checking on arrays
  • Manual memory management (malloc/free)
  • Direct pointer manipulation
  • No built-in string type with safety guarantees
Key Insight: The same features that make C powerful also make it dangerous.

Stack Frames

What Happens During a Function Call

  1. Arguments pushed onto the stack
  2. Return address pushed — where to resume after return
  3. Old EBP saved — preserves caller's frame pointer
  4. New stack frame created — EBP = ESP, locals allocated

Stack Frame Layout

  High Addresses
┌──────────────────┐
│   Arguments      │  ← passed by caller
├──────────────────┤
│  Return Address  │  ← where to go after return
├──────────────────┤
│    Saved EBP     │  ← caller's frame pointer
├──────────────────┤
│  Local Variables │  ← function's own data
└──────────────────┘
  Low Addresses (ESP)
Security Implication: The return address sits above local variables. A local buffer overflow can overwrite it.
💥

Buffer Overflow

What Is a Buffer Overflow?

Writing beyond allocated memory bounds, potentially overwriting nearby memory such as variables or the return address.

Why They Happen in C

  • No bounds checking — C does not verify array indices
  • Unsafe functions — strcpy(), gets() copy without size limits
  • Unvalidated user input — no automatic sanitisation

Consequences

Level 1Crash

Segmentation fault

Level 2Data Corruption

Overwritten variables

Level 3Security Bypass

Auth flags overwritten

Level 4Code Execution

Full system compromise

🎯

Stack Overflow Exploits

Vulnerable Code Example

char buffer[12];
strcpy(buffer, str);  // ⚠️ No bounds checking!

If str exceeds 12 bytes, it overwrites adjacent stack data including the return address.

Controlling the Return Address

If an attacker controls the return address, they can redirect execution to malicious code — achieving arbitrary code execution.

Critical: This is the foundation of all stack-based exploitation techniques covered in Week 3.
