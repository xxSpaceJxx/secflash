Same Origin Policy (SOP)

The SOP enforces that scripts can only access data from the same domain and protocol. An origin is defined by the combination of scheme + host + port.

This prevents a malicious page from reading sensitive data from another site (e.g., your bank).

SQL Injection

What Is SQL Injection?

Injecting malicious SQL through user input because the application treats input as executable SQL code rather than data.

-- Intended query:
SELECT * FROM users WHERE name = 'bob' AND pass = 'secret'

-- Injected input: bob' OR 5=5 --
SELECT * FROM users WHERE name = 'bob' OR 5=5 --' AND pass = 'secret'
                                         ^^^^^^     ^^
                                     always true    commented out

How bob' OR 5=5 -- Bypasses Login

OR 5=5 is always true, so the WHERE clause matches every row in the table. The -- comments out the rest of the query (the password check).

DROP TABLE Injection

An attacker can inject ; DROP TABLE users -- to permanently delete the entire users table. This is a destructive attack that may be irreversible without backups.

Second-Order SQL Injection

Malicious data is stored safely in the database, then later reused unsafely in another query. This makes it harder to detect because the injection doesn't happen at the initial input point.

SQLi Defences

Why Escaping Quotes Is Insufficient

While escaping single quotes stops basic string injection, it fails against:

  • Numeric injection — no quotes needed for integer fields
  • Second-order injection — data escaped on input but not when reused
  • Encoding tricks — alternative character encodings bypass filters

Parameterised Queries — The Gold Standard

A parameterised query separates SQL code from data using placeholders. The database engine treats bound values strictly as data, never as executable code.

// ❌ VULNERABLE — string concatenation
query = "SELECT * FROM users WHERE name='" + input + "'";

// ✅ SAFE — parameterised query
query = "SELECT * FROM users WHERE name = ?";
stmt.bind(1, input);
Why it works: The database parser processes the SQL structure first, then binds data separately. Injected SQL is treated as a literal string value.

Browser Security

Browser Sandbox

A restriction system limiting JavaScript's access to the OS and other browser contexts. Scripts run in an isolated environment and cannot freely access the file system, other tabs, or system resources.

Unifying Security Principle

Never treat untrusted input as executable code. This principle connects buffer overflows (machine code injection), format strings (format specifier injection), SQL injection (SQL code injection), and XSS (JavaScript injection).
