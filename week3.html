Exploitation Basics

The Main Attack Vector

In a stack-based buffer overflow, the primary attack vector is overwriting the return address so that when the function returns, execution jumps to an attacker-controlled address instead of the legitimate caller.

The 3 Steps of a Buffer Overflow Exploit

1. Overflow the buffer
→
2. Overwrite return address
→
3. Redirect execution
📦

Payloads & NOP Sleds

NOP Sled

A NOP sled is a sequence of NOP (No Operation) instructions placed before shellcode. The CPU "slides" through them into the shellcode, making exploits more reliable because the exact jump address doesn't need to be perfect.

Malicious Payload Structure

┌─────────┬────────────────────┬──────────┬────────────┐
│ padding │ new return address │ NOP sled │  shellcode │
└─────────┴────────────────────┴──────────┴────────────┘
  • Padding — fills the buffer up to the return address
  • New return address — points into the NOP sled
  • NOP sled — slides execution into shellcode
  • Shellcode — the actual malicious code
🐚

Shellcode

What Is Shellcode?

Shellcode is small malicious machine code injected by an attacker, typically designed to spawn a shell (/bin/sh) or execute arbitrary commands. It must be position-independent and avoid null bytes (which terminate strings in C).

🧬

Advanced Attacks

Return-to-libc

Instead of injecting shellcode, this attack redirects execution to existing library functions like system(). It bypasses the NX bit because it uses existing executable code rather than code on the stack.

Return-Oriented Programming (ROP)

An advanced technique chaining small existing instruction sequences called gadgets — each ending in ret. By carefully arranging return addresses on the stack, attackers build arbitrary programs from existing code fragments.

Comparison of Attack Techniques

🔴 Shellcode

Injects new code onto the stack and executes it. Blocked by NX bit.

🟡 Return-to-libc

Calls an existing function (e.g. system()). Bypasses NX. Limited to single function calls.

🟣 ROP

Chains existing gadgets for arbitrary computation. Bypasses NX. Most powerful technique.

🛡️

Defences

ASLR — Address Space Layout Randomization

Randomises memory addresses each time a program runs, making exploits unreliable because attackers can't predict where code or data will be.

Bypasses: Brute force (try many addresses), information leaks (discover addresses at runtime).

Stack Canary

A random value placed between the buffer and the return address. Before returning, the program checks if the canary was modified. If it was, the overflow is detected and the program crashes safely.

NX Bit (Non-Executable Memory)

A hardware defence that marks memory regions (like the stack) as non-executable. Even if shellcode is injected, it cannot run.

Defence vs. Bypass Summary

DefenceHow It WorksBypass Method
NX BitStack is non-executableReturn-to-libc / ROP
ASLRRandomised addressesInfo leaks / brute force
CanariesDetect stack corruptionBypass or leak canary value

The Best Defence

Secure coding practices — bounds checking, input validation, and avoiding unsafe functions like gets() and strcpy(). Hardware defences are important but can be bypassed; writing safe code is the most reliable mitigation.

Remember: All the hardware defences add layers, but secure coding is the foundation.
