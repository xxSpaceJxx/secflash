Secure Software Development Lifecycle

Secure by Design

Security should be integrated into every phase of software development rather than added later as an afterthought. The goal is to build software that remains secure even under malicious attack.

Risk Management

Key Steps in Applied Risk Management

  1. Identify assets/business context — what needs protecting
  2. Identify technical and business risks — what could go wrong
  3. Prioritise risks — which risks matter most
  4. Define mitigation strategies — how to reduce risk
  5. Implement and validate fixes — apply and verify mitigations
🗺️

Threat Modelling

What Is Threat Modelling?

A structured process used to identify, analyse, and mitigate threats against a system. It creates a model of the system and explicitly defines what attackers are capable of doing.

Threat modelling answers four key questions:

  • What are we building? — system architecture
  • What can go wrong? — threat identification
  • What are we going to do about it? — mitigations
  • Did we do a good job? — validation
🎯

STRIDE Threat Model

The STRIDE Categories

STRIDE is a framework for categorising security threats. Each letter represents a type of threat:

🎭 Spoofing

Impersonating a user or system. Violates authentication.

✏️ Tampering

Unauthorised modification of data. Violates integrity.

🚫 Repudiation

Denying an action was performed. Violates non-repudiation.

📤 Information Disclosure

Exposing data to unauthorised parties. Violates confidentiality.

⛔ Denial of Service

Making a system unavailable. Violates availability.

👑 Elevation of Privilege

Gaining unauthorised access levels. Violates authorisation.

Secure Design Principles

Core Principles

🔑

Least Privilege

Every user and process should operate with the minimum privileges necessary. Limits damage if compromised.

🧅

Defence in Depth

Use multiple layers of security so if one fails, others still protect the system.

💻

Secure Coding

Three Key Techniques for User Input

  1. Input validation — ensure input is acceptable (type, length, range, format)
  2. Canonicalization — convert data into a standard form before validation (e.g., resolve ../ in paths)
  3. Sanitization — remove, encode, or escape dangerous input characters
Defence in Depth Applied: Use all three techniques together. Validate first, canonicalize, then sanitize. Each layer catches what the others might miss.
